# 顧客管理のルール

2026-11-20 に高田さんと決めたこと。

## 1. 顧客台帳（正本）

- 置き場所：SharePoint サイト `CoPresiden` のリスト「顧客台帳」
- 会社名・連絡先・契約内容などの個人情報と、入稿の合言葉は、顧客台帳だけに書く。このリポジトリ（公開）には書かない
- このリポジトリに書いてよいのは、顧客コードと、人が見分けるための短い呼び名（例：A.EN）まで

### 列（2026-11-20 高田さんが作ったリスト `Lists/Customers`）

CSV の見出しは内部名（左から2列目）になる。

| 表示名 | 内部名（CSVの見出し） | 種類 | 夜の処理で使うか |
| --- | --- | --- | --- |
| 顧客コード | `Title` | 1行テキスト | 使う（例：C0001） |
| 呼び名 | `name` | 1行テキスト | 使う（知らせ・記録。例：AEN_AYA） |
| 会社名 | `CompanyName` | 1行テキスト | 使わない |
| 会社よみがな | `CompanyKana` | 1行テキスト | 使わない |
| 社長名 | `President` | 1行テキスト | 使わない |
| アバター愛称 | `AvatarName` | 1行テキスト | （用途を確認中） |
| 会社愛称 | `CompanyShort` | 1行テキスト | （用途を確認中） |
| 連絡先電話番号 | `PhoneCode` | 1行テキスト | 使わない |
| お知らせメール送信先 | `MailAddress` | 1行テキスト | 使う |
| 状態 | `Status` | 1行テキスト | 使う（値は下の4の表のとおりに書く） |
| 契約日 | `ContractDate` | 日付と時刻 | 使わない |
| プラン | `PlanName` | 1行テキスト | 使わない |
| シリーズ数 | `SeriesNum` | 数値 | 使わない |
| 声顔同意日 | `consentDate` | 日付と時刻 | 使う（空なら作らない） |
| 合言葉 | `Word` | 1行テキスト | 使う（振り分け） |
| SharePointフォルダー | `SharePointFolder` | 1行テキスト | 使う |
| 解約日 | `CancellationDate` | 日付と時刻 | 使わない |
| 解約メモ | `CancellationNote` | 複数行テキスト | 使わない（消すか返すかもここに書く） |
| メモ | `memo` | 複数行テキスト | 使わない（HTMLで書き出される） |

## 2. 顧客コード

- 契約を結んだときに付ける。`C` と4桁の連番（C0001、C0002…）。一度付けたら変えない。解約したお客様のコードも使い回さない
- 契約のあとの作業は、すべて顧客コードで扱う

| 場所 | 名前 |
| --- | --- |
| SharePoint（InformationExchange） | `<顧客コード>`（例：`C0001`）の下に `01_入稿`・`02_素材`・`03_完成`・`04_承認記録` |
| このリポジトリ | `customers/<顧客コード>/`（台帳 `ledger.md`、シリーズ設定 `series.md`、作業記録 `work/`） |
| 声・アバター | 非公開の置き場所（`docs/assets.md`、未決定） |
| 作業記録・承認記録・知らせメール | 顧客コードを書く |

## 3. 入稿の合言葉

- 入稿フォームの URL の末尾 `?textbox20=<合言葉>` で渡す（Jotform の隠し項目。入稿の PDF では「お客様ID」と出る）
- 合言葉は顧客コードとは別にする。URL が漏れたら、合言葉だけを作り直す（フォルダーなどの名前は変えない）
- 夜の処理は、合言葉を顧客台帳で顧客コードに引き当てる。台帳にない合言葉、または古い合言葉の入稿は振り分けず、高田さんに知らせる

## 4. 状態と夜の処理

| 状態 | 意味 | 夜の処理 |
| --- | --- | --- |
| 契約済 | 契約を結び、顧客コードを付けた | 作らない |
| 面談済 | 台帳・シリーズ設定ができた | 作らない |
| 素材あり | 声とアバターができた | 作らない（試作は高田さんの指示があれば作る） |
| 運用中 | 入稿を受け付ける | 作る |
| 停止 | 一時的に止めている | 作らずに知らせる |
| 解約 | 契約が終わった | 作らずに知らせる。素材は「解約メモ」に従い消すか返す |

- 状態は1行テキストなので、上の表の言葉をそのまま書く。表にない言葉のお客様は作らずに知らせる
- 「声顔同意日」が空のお客様は、状態にかかわらず作らない

## 5. 契約から運用までの順番

1. 契約 → 顧客台帳に行を足し、顧客コードを付ける（状態：契約済）
2. SharePoint にお客様のフォルダーを作る。このリポジトリに `customers/<顧客コード>/` を作る
3. 面談 → 台帳・シリーズ設定（状態：面談済）
4. 声とアバターを作る（別の工程）→ 同意日を書く（状態：素材あり）
5. 入稿の合言葉を作り、入稿 URL をお客様に渡す（状態：運用中）

## 6. 夜の処理用の書き出し（2026-11-20 決定）

この作業場所の Microsoft 365 の道具は、SharePoint のリストを読めない（ファイルは読める）。そのため Power Automate で、リストの変更のたびに、夜の処理に要る列だけを CSV に書き出す。

- 正本はリスト。CSV は直さない（次の書き出しで上書きされる）
- 書き出し先：SharePoint サイト `CoPresiden` のドキュメントライブラリ `System` の `customers.csv`。`System` はお客様と共有しない
- 書き出す列：いまはリストの全部の列（Power Automate の既定）。夜の処理は見出しの名前で読む（列の順番に頼らない）
  - 値が空の列は、見出しごと出ないことがある（例：解約日）。夜の処理に要る列（`Title`・`name`・`MailAddress`・`Status`・`consentDate`・`Word`・`SharePointFolder`）が無いときは作らずに知らせる
  - 会社名・電話などの個人情報も含まれる。夜の処理はこれらを作業記録・ログ・リポジトリに写さない
- フロー：「項目が作成または変更されたとき」→「複数の項目の取得」→「CSV テーブルの作成」（全部の列）→「ファイルの作成」
- リストの行は消さない（消してもフローが動かない）。契約が終わったら状態を「解約」にする
- 夜の処理は、最初に `customers.csv` を読む。読めない・見出しが違うときは作らず、高田さんに知らせる
